## 1. Решения 05.10.2026 — БД и журнал

### 1.1. Перенос участков и нарядов в Редактирование

**Правило:** создание и удаление участков и нарядов — **только
во вкладке «Редактирование»**. В БД этих действий нет.

**Причина:** все действия над структурой данных (участок → наряд →
проба) в одном месте. Оператор не путается, где что создавать.

**Где:**

- `EditViewModel` — методы `addArea`, `deleteArea`, `addOrder`,
  `deleteOrder`.
- `EditScreen` — кнопка «+ Участок» над деревом; иконки «+ Наряд»
  и «Удалить» у каждого участка; «Удалить» у каждого наряда.
- Диалоги `TextInputDialog` / `ConfirmDialog` — в `EditScreen.kt`.

**Реализовано в `db-restructure-edit` и `db-restructure-edit-2`.**

### 1.2. Инфо-панель вместо списка в БД

**Правило:** на вкладке БД нет списка участков, нарядов и проб.
Вместо него — постоянная инфо-панель.

**Что в панели:**

- Путь к файлу БД (в одну строку, с обрезкой).
- Размер БД, размер папки фото.
- Дата последнего изменения.
- Счётчики: участков, нарядов, скважин, проб, фото, заметок.

**Обновление:** автоматически при заходе на вкладку + кнопка
«Обновить» в заголовке.

**Что удалено:**

- `DbInfoDialog.kt` — файл удалён.
- Кнопка «Инфо» из ряда кнопок — не нужна.
- Стейты `areas`, `selectedArea`, `orders`, `selectedOrder`,
  `samples` в `DbViewModel`.

**Реализовано в `db-restructure-edit-2`.**

### 1.3. Журнал аудита (`logs`)

**Правило:** в приложении ведётся журнал действий — отдельная БД
+ файловый архив.

**Два хранилища:**

- `logs.db` — отдельная БД (не в основной схеме). Записи с
  фильтрами, стейт-машиной, категориями.
- `Downloads/GeoSampleManager/.logs/YYYY-MM-DD.log` — человекочитаемый
  файловый архив, по одному файлу на день.

**Почему отдельная БД, а не таблица в основной:**

- Основная БД стирается при `clean` — а событие `clean` должно
  быть в истории.
- Основная БД заменяется при restore / rollback / merge — журнал
  должен пережить эти операции.
- Миграция основной БД 2→3 не нужна.

**Почему отдельный файл, а не только БД:**

- Админ может читать журнал через файловый менеджер / USB, без
  adb и без root.
- Не теряется при сносе приложения.

**Папка `.logs/` со скрытой точкой** — рабочий не видит, случайно
не удалит. Доступ — у админа.

**Категории:** `app`, `nav`, `search`, `voice`, `mark`, `edit`,
`db`, `error`.

**Формат `summary`:** русская фраза в прошедшем времени, без
английского и без технического жаргона. Технические данные (id,
JSON, stacktrace) — только в `details`.

**Формат файловой строки:**
05.10.2026 14:32:05 [ИНФО] [Приложение] Приложение запущено

text

Unicode-маркеры уровней: `●` (инфо), `⚠` (внимание), `✕` (ошибка).
Details раскрываются построчно через `└ key: value`.

**Ротация:** 10 000 записей в БД, файлы не ротируются
(архив по дням).

**Очистка:**

- В UI — только `logs.db`, с двойным диалогом и чек-боксом
  подтверждения.
- Файлы в `.logs/` из UI не удаляются. Только через файловый
  менеджер (админ).

**Проверки в устройстве:** см. `TESTING.md` — `data/logs/`
и раздел «Что НЕ покрываем».

**Реализовано в `logs-1` … `logs-8b`.**

### 1.4. Диагностика БД

**Правило:** диагностика ищет проблемы в БД и позволяет исправить
их с авто-бэкапом `pre_diagnostics_*`.

**Четыре типа проблем:**

1. Наряды без участка.
2. Пробы без наряда.
3. Битые ссылки на фото (запись есть, файла нет).
4. Флаг `has_photo = false`, но файлы на диске есть.

**Пункты 3 и 5 ТЗ объединены** — «запись в `sample_images` есть,
файла нет» → удалить запись + сбросить флаг. Логически это одна
операция.

**UI:** единый список с чек-боксами и группировкой по типу
проблемы. Кнопка «Исправить выбранное».

**Реализовано в `db-diagnostics`.**

## 2. Решения 25.09.2026 — закрытие серии e4

### 2.1. Честная ошибка вместо fallback (pin-7)

**Было (pin-4, pin-5, pin-6):**
- Vosk путает «четвёртая» ↔ «четырнадцатая» (4 ↔ 14).
- Fallback: если проба 14 не найдена — пробуем 4, и наоборот.
- Расширено до 40↔4, 400↔4, 4000↔4.
- В pin-6 добавили показ подмены: «Распознано X → Y».

**Проблема (device-check):**
- Vosk путает в **обе стороны**. Если юзер сказал «четырнадцатая» и
  хотел 14, а её нет — fallback молча отмечал 4. Неправильное действие.
- Отличить «юзер хотел 4» от «юзер хотел 14» по тексту Vosk нельзя:
  в обоих случаях `text=«четырнадцатая»`.

**Решение (pin-7):**
- Fallback **убран полностью**.
- Проба с распознанным номером есть → отметка.
- Пробы нет → `MarkOrdinalNotFound(ordinal, hintOrdinal)`.
- `hintOrdinal` — «спорный» двойник (14 → 4, 40 → 4, 400 → 4,
  4000 → 4), если он есть. Для 1..3 и чисел типа 20, 25 — null.
- UI и голос: «Пробы №14 нет. Если нужна №4 — произнесите „четыре".»
- **Количественные числа Vosk распознаёт чётко** — уточнение числом
  работает надёжно.
- **И-35** — Vosk путает «четвёртая» → «четырнадцатая». Лечится
  в `e4d`.

**Для 1..3 подсказок нет:** корни «перв/втор/трет» фонетически не
путаются с 10/100/1000.

### 2.2. Маркеры намерения (e4-markers)

**Правило:** глагол **без номера** → маркер намерения. Глагол **с
номером** в той же фразе → сразу команда.

**Примеры:**
- «отметь» → `AWAITING_MARK` → «Какую?» → «четвёртую» → `MarkOrdinal(4)`.
- «отметь четвёртую» → сразу `MarkOrdinal(4)`. Без вопроса.
- «отметь пять шесть» → `MarkByNumbers([5, 6])`.

**Для снятия и отложения — аналогично.**

**Тайм-аут:** 30 сек, предупреждение на 20-й. По тайм-ауту — сброс
в `LISTENING`.

### 2.3. Подтверждение массовых (e4-markers)

**Правило:** массовые действия требуют подтверждения голосом.
Одиночные — нет.

**Что подтверждаем:**
- «отметь все» → `MarkAll`.
- «снять все» → `ClearAll`.

**Что НЕ подтверждаем:**
- Одиночные `MarkOrdinal`, `ClearOrdinal`, `MarkCurrent`, `ClearLast`.
- `Unpostpone`.

**Что НЕ реализуем голосом вообще:**
- **Удаление проб** — только UI с чек-боксом «Пересчитать №».

**Фразы подтверждения:**
- «подтверждаю» / «подтвердить» → выполнить.
- «отменяю» / «отменить» / «отмена» → отменить.
- «стоп» → закрыть сессию.
- Молчание 30 сек → автоотмена.

**Простое «да» / «нет» не используется** — Vosk их путает с другими
командами. Только явные формы.

### 2.4. Очередь веса после массовой отметки (e4-weight-queue)

**Правило:** «отметь все» + подтверждение → отметить всё, что можно,
потом по одной спрашивать вес для холостых/ВК без веса.

**Порядок очереди:** как в списке (сверху вниз).

**Формат вопроса:** «Холостая, 5-я. Вес?» (тип + порядковый номер).

**«Пропустить»:** оставить пробу неотмеченной, перейти к следующей.

**«Стоп»:** вся сессия. **«Пауза»:** очередь сохраняется.

**Тайм-аут:** 30 сек / предупреждение на 20-й. По тайм-ауту — очередь
сбрасывается.

**Завершение:** если `skipped == 0` → «Все пробы скважины отмечены.»
, иначе «Отмечено N. Пропущено M. Очередь веса завершена.»

### 2.5. Префиксы по буквам раздельно (e4-prefix-1)

**Правило:** TTS произносит префикс по буквам раздельно: «ка пэ дэ»,
«эн вэ», «даблю».

**Vosk:** звуки букв добавлены в грамматику. Слышит «ка», «пэ», «дэ»
отдельными словами → `VoicePrefixResolver` собирает в буквы.

**Синхронизация:** TTS и Vosk используют один набор произношений.
Слово в слово — что услышал, то и произнёс.

**W:** «даблю» (было «дабл-ю» — рассогласование).

### 2.6. Мимикрия везде (e4-speak-1, e4-markers-2)

**Правило:** ГП произносит номера скважин и проб **как человек** во
всех местах, где он их называет.

**Метод:** `VoiceSpeaker.spellMimicry(text)`.
- Строка = «префикс + цифры» → разбить.
- Префикс — по буквам раздельно.
- Цифры — `splitLikeHuman`: чётная длина → пары, нечётная → первая 3,
  потом пары.

**Примеры:**
- `NV1366` → «эн вэ тринадцать шестьдесят шесть»
- `KPD1090031` → «ка пэ дэ сто девять ноль ноль тридцать один»
- `109003101` → «сто девять ноль ноль тридцать один ноль один»

**Где применяется:** `voicePostponeOrdinal`, `voiceClearOrdinal`,
`oldSortBehaviour`, `VoiceDialog.spokenNumberOf`, `VoiceDialog.Marked`
fallback, `VoiceDialog.buildWeightQueueQuestionPhrase` и др.

### 2.7. «Распознано» = канонический номер (e4-fix-voice-1)

**Правило:** поле «Распознано» в панели ГП показывает **канонический
номер из БД**, а не сырой текст Vosk.

- Если нашли → `FoundOne.query` (`NV1366`).
- Если не нашли → сырой текст Vosk.

**Зачем:** сырой текст «эн вэ сто девять ноль ноль тридцать один»
нечитаем. Пользователю нужен результат, а не фонетика.

### 2.8. Подсказка при снятии (e4-fix-voice-1)

**Правило:** если при снятии проба не найдена — та же подсказка, что
при отметке: «Пробы №14 нет. Если нужна №4 — произнесите „четыре".»

Раньше работало только для `MarkOrdinal`. Теперь и для `ClearOrdinal`.

### 2.9. SORT + attention (e4-fix-voice-1)

**Правило:** в SORT-режиме тоже проверяется выбранный участок и наряд.
Если не совпадает — «Другой участок / Другой наряд. Выберите на экране.»

Раньше в SORT `attentionReason` был жёстко `null` — предупреждения
не было.

### 2.10. Кнопка «Наверх» (e4-ui-1)

**Правило:** в длинном списке проб появляется маленькая круглая FAB
со стрелкой ↑ внизу справа.

- Появление: `firstVisibleItemIndex > 10`.
- Скролл — мгновенный (`scrollToItem(0)`, не `animateScrollToItem`).
- Позиция: `padding(end = 16.dp, bottom = 100.dp)` — над панелью ГП.

### 2.11. Точечные правки в файлах (правило для ИИ)

**Правило:** при выдаче файла с пометкой «Заменить полностью» —
правки только там, где нужно. Комментарии, форматирование, пустые
строки, порядок разделов — сохранять как в исходнике.

**Почему:** пользователь сверяет diff. Если в diff всплывают удалённые
комментарии или переставленные блоки — это шум, мешает проверке.

**Проверка:** перед отправкой спросить — «это изменение нужно для
задачи?». Если нет — не трогать.

**Зафиксировано в `AI_RULES.md` §23.**

## 3. Решения 24.09.2026 — архитектура ГП

### 3.1. Свод путей поиска
- **UI и голос — один путь.** `QueryNormalizer` → `QueryTokenizer` →
  `DigitGrouper` → `SearchService`. Реализовано в `e4e-bundle`.

### 3.2. Pin скважины
- После `FoundOne` — скважина закрепляется.
- В `FOUND_PINNED` любое голое число → `MarkOrdinal`, не `Search`.
- Фраза из числительных склеивается.
- Выходы: «следующая», «следующая X», «отмена», ручной ввод UI.
- Реализовано в `e4-pin-1`, `e4-pin-3`, `e4-pin-4`.

### 3.3. Очередь мультизапроса
- Два и более запроса, все дали единственное попадание → очередь.
- Реализовано в `e4-pin-2`, `e4-pin-3`.

### 3.4. Attention-переключение
- `FOUND_OTHER_AREA` / `FOUND_OTHER_ORDER` / `FOUND_MULTIPLE` →
  старое поведение (Message).
- Работает и в SORT (`e4-fix-voice-1`).

### 3.5. Маркеры намерения
- «Отметь» → `AWAITING_MARK`.
- «Снять» → `AWAITING_CLEAR`.
- «Вес» → `AWAITING_WEIGHT`.
- «Найди» → переключение в ПОИСК.
- «Отложить» → `AWAITING_POSTPONE`.
- Реализовано в `e4-markers`.

### 3.6. Динамические словари Vosk
- Сужение только в узких состояниях.
- `LISTENING`, `FOUND_PINNED` — не сужать.
- Пересоздание `Recognizer` — во время TTS.
- **Планируется в `e4-dicts` и `e4d`.**

### 3.7. Мимикрия TTS
- Группы без запятых, через пробел.
- Префикс — одним словом раньше, теперь по буквам раздельно.
- Реализовано в `e4e-bundle`, уточнено в `e4-prefix-1`, `e4-speak-1`.

### 3.8. Приоритеты поиска в выбранном наряде
1. Строгий по всей БД.
2. Префикс скважины (левые цифры).
3. Номер пробы (`sampleNumber`, слева).
- **Планируется в `e4-search-context`.**

### 3.9. Поиск при 0 попаданий
- Состояние `AWAITING_NOT_FOUND_CHOICE`.
- **Не реализовано.**

### 3.10. Конец очереди
- «Очередь пуста. Скажите „следующая" для нового запроса.»
- Реализовано в `e4-pin-2`.

### 3.11. Команды всегда
- Stop, Pause, Undo, Redo, Отмена, Помощь.

### 3.12. Отменённые решения
- `e4c` — числительные в `QueryTokenizer`. Откачен.
- `e4f` — подтверждение веса > 30. Отменён.
- `e4h` — таблица команд. Отложен.
- **`e4-pin-6` — показ подмены.** Откачен в `e4-pin-7`.

### 3.13. Кулдаун TTS
- 250 мс (`e4-fix-2`).

### 3.14. «Четвертью» в грамматике
- Убрано (`e4-fix-1`).

### 3.16. Вес «X сотни»
- «Два семьсот» → 2.7. Реализовано в `e4-pin-3`.

### 3.17. «Следующая X» — одной командой
- «Следующая 1525» → `Find("1525")`. Реализовано в `e4-pin-3`.

### 3.18. Очередь — только если все уникальны
- Реализовано в `e4-pin-2`.

### 3.19. Префикс «Найдено N скважин»
- `FoundOne.queueSize > 1` → префикс в VoiceDialog. Реализовано в `e4-pin-3`.

### 3.20. Очередь — только мультизапрос
- Одиночный поиск не строит очередь. Реализовано в `e4-pin-2`.

### 3.21. Подтверждение массовых (первое)
- Массовые действия требуют подтверждения.
- Реализовано в `e4-markers`.

### 3.22. Accent fix в озвучке (pin-7)
- Слово «Распознано» убрано из голоса.

## 4. Экран «Сверка и поиск»

### Общее
- Одна вкладка. Два неявных режима: Поиск и Сверка.

### Селекторы
- Участок, Наряд — опциональны.
- Наряд нельзя выбрать без участка.
- Шестерёнка — настройки наряда.

### Поле поиска
- Один или несколько номеров через пробел.
- Крестик — очищает.
- Ищет по всей БД.
- Дебаунс 500 мс.

### Режимы поиска
1. Ничего не выбрано → строгое совпадение.
2. Выбран участок → строгое; участок — приоритет.
3. Выбраны участок И наряд → строгое или префикс по № пробы.

**Уточнение 24.09.2026:** при выбранном наряде сначала строгий по всей
БД, если не нашлось — префикс скважины, потом — номер пробы.
