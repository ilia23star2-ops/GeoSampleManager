# SHADOW_STATS.md — теневая статистика (черновик)

> **Статус:** черновик. Спецификация серии 5.10.
> **Не реализовано.** Код не писать, пока фича 5.9 не в main.
>
> Цель: инструмент админа для проверки реальной работы ОП и
> выявления багов. Скрыт от ОП.

---

## 1. Зачем

1. **Поймать реальные ошибки.** ОП говорит «сломалось» — смотрим,
   что на самом деле произошло: краш, ошибка импорта, или ОП сам
   удалил БД.
2. **Проверить реальное использование.** Не «включил и положил»,
   а работал: сколько активных минут, какие действия, сколько
   нарядов обработал.
3. **Приоритеты для разработки.** Что чаще используется, где
   больше всего ошибок, какие голосовые фразы Vosk разбирает
   неверно.

**Теневая** = ОП не знает о ней. UI спрятан.

---

## 2. Модель
День → Сессии → Визиты вкладок → События

text

- **День.** Один день, `YYYY-MM-DD`.
- **Сессия.** Один запуск приложения. Запустил → вышел (или
  краш). Сессий в день — несколько.
- **Визит.** Пребывание на одной вкладке: вошёл → ушёл.
- **Событие.** Атомарное действие: поиск, отметка, ошибка,
  голосовая команда.

### Рабочее окно

- **Пн–Пт, 08:00–17:00** — рабочее.
- **Вне окна** — пишется, но помечено серым. В отчёт по
  «реальной работе» не идёт.
- **День** считается от **первого запуска** в окне, до конца
  дня (17:00 или фактического выхода).

## 3. Что записываем

### 3.1. Сессии

- `started_at`, `ended_at`.
- `active_seconds` — были действия.
- `idle_seconds` — простой (порог 60 сек тишины).
- Разделение: `foreground` / `background` / `screen_off`.

### 3.2. Визиты вкладок

- `tab`, `from`, `to`, `duration`.
- Для timeline и статистики по времени.

### 3.3. Фазы наряда

**Определение:**
- **Начало работы с нарядом:** первое действие с упоминанием
  наряда.
- **Фаза «Поиск»:** действия без отметок.
- **Фаза «Сверка»:** действия с отметками.

**Формула:**
- Запрос Q1 → Q2 (нет отметок) → **Поиск**.
- Q3 → M1 → M3 → Q4 (есть отметки) → **Поиск / Сверка / Поиск**.
    - Q3 → M1 — Поиск.
    - M1 → M3 — Сверка.
    - M3 → Q4 — Поиск.

**Возврат в Поиск:** если 5+ действий без отметок после Сверки —
возврат в Поиск.

**Завершение наряда:**
- Все пробы `found = true` — **готов**.
- Только поиск проведён (всё, что нужно, найдено, но не
  отмечено) — **«готов наполовину»**.
- Ничего не было — **не начат**.

### 3.4. События

Формат: время + тип + summary + details.

**Уровни:**
- `info` — обычное действие.
- `warn` — внимание.
- `error` — критично.

**Авто-повышение:** серия неудач (5+ поисков подряд не нашли) →
`warn`.

**Голос — обязательно пара:**
- `raw` (что услышал Vosk);
- `parsed` (что понял парсер).
- Расхождение — `warn`. Для улучшения ГП.

### 3.5. Проблемы БД (в день)

- Сироты, битые ссылки, несоответствие флагов.

### 3.6. Дневной отчёт

Авто-сводка за рабочий день:
- запусков;
- активного/простой;
- открыто нарядов / отмечено проб;
- поисков (успешных / нет);
- ошибок по типам;
- голосовых команд (понято / нет).

## 4. Хранение

### 4.1. Две системы

- **`stats.db`** — активная БД, `filesDir/stats/active.db`. Один
  файл на текущий месяц.
- **`.stats/YYYY-MM-DD.json`** — дневной архив. Создаётся по
  кнопке «Экспорт» в админке (или автоматически при первом
  запуске нового дня). Формат — читаемый.

### 4.2. Ротация

- Раз в месяц — `active.db` → `filesDir/stats/archive/YYYY-MM.db`
  (read-only).
- Удаление — только вручную в админке (кнопка «Удалить старые»).

### 4.3. `logs.db`

- **Удаляется** при первом старте новой версии (после апдейта).
- События переносятся в `stats.db` как часть сессии.
- UI журнала из Настроек убираем.

### 4.4. Immutability

- Живые данные — в `filesDir`, ОП не достанет без root.
- UI-кнопки «Очистить журнал» **нет**.
- Экспорт `.stats/*.json` — только по кнопке админа.

### 5.3. Гибридное отображение событий

- **Плашка сверху:** «⚠ 3 ошибки, 5 предупреждений» → тап →
  только они.
- **Лента:** ошибки, warn, потом свёрнутые по визитам обычные.
- **Раскрытие визита:** тап → список микрособытий с результатами.

### 5.4. Timeline

- Цветные полоски по вкладкам.
- Активное время — насыщенный цвет, простой — приглушённый.

### 5.5. Метрики

- Сводка по дню.
- Список незавершённых нарядов со статусами Поиск/Сверка.
- Топы (2-й этап).

## 9. Что обсудили и решили

- **Начало дня:** первый запуск после 08:00.
- **Вне окна:** пишем, помечаем серым.
- **UI журнала:** из Настроек убираем, только в админке.
- **`logs.db`:** удаляем при апдейте.
- **Экспорт:** по кнопке, живые данные — приватно.
- **Голос:** `raw` от Vosk vs `parsed`. Расхождение = warn.
- **Пользователь пишет «норм»** для теста пачки.
- **Фазы:** формула выше (§3.3).
- **Отложенные:** по группам (участок / наряд).
- **Проблемы БД:** только SQL-сироты в лёгкой проверке,
  полная — по кнопке.
- **Скрытый вход:** долгий тап на версии.
