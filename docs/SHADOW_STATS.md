> **Серия:** 5.10.

## 0. О чём этот документ

Спецификация системы теневой статистики: модель, схема БД, формат
экспорта, UI админ-панели, разбивка на пачки реализации.

**Что НЕ входит:**
- Изменения основной БД (`geosamples.db`) — не трогаем.
- Изменения публичной сигнатуры существующих репозиториев — по
  возможности нет.
- UI ОП — теневую статистику ОП не видит.

---

## 1. Зачем

Три задачи.

1. **Поймать реальные ошибки.** ОП говорит «сломалось» — смотрим,
   что на самом деле произошло: краш, ошибка импорта, или ОП сам
   удалил БД.

2. **Проверить реальное использование.** Не «включил и положил»,
   а работал: сколько активных минут, какие действия, сколько
   нарядов обработал.

3. **Приоритеты разработки.** Что чаще используется, где больше
   ошибок, какие голосовые фразы Vosk разбирает неверно.

**Теневая** = ОП не знает о ней. UI спрятан.

## 2. Модель
День → Сессии → Визиты вкладок → События

text

- **День.** `YYYY-MM-DD`, рабочее окно.
- **Сессия.** Один запуск приложения. Запустил → вышел (или
  краш). Сессий в день — несколько.
- **Визит.** Пребывание на одной вкладке: вошёл → ушёл.
- **Событие.** Атомарное действие: поиск, отметка, ошибка,
  голосовая команда.

### 2.1. Рабочее окно

- **Пн–Пт, 08:00–17:00** — рабочее.
- **Вне окна** — события пишутся, но помечены серым. В отчёт
  по «реальной работе» не идут (для разработки, для личного).
- **День** считается от **первого запуска в окне** до **17:00**
  или до фактического выхода, если раньше.
- **Если запуск после 17:00** — событие не входит в рабочий
  день, сессия помечается «вне окна».

### 2.2. Порог простоя

- **60 сек** без событий — начало простоя.
- **Экран выключен** (`ACTION_SCREEN_OFF`) — простой.
- **Приложение свёрнуто** (`onPause`) — простой.
- **Активная сессия с приложением в фоне** — фон учитывается
  отдельно, не в простой.

## 3. Схема `stats.db`

SQLite, Room. Отдельная БД (не в основной). Путь:
`filesDir/stats/active.db` (текущий месяц) +
`filesDir/stats/archive/YYYY-MM.db` (архивы).

### 3.1. `sessions`

| Поле | Тип | Описание |
|---|---|---|
| `id` | Long PK | Автогенерация |
| `started_at` | Long | Timestamp запуска |
| `ended_at` | Long? | Timestamp выхода (null если не закрыта — краш) |
| `active_sec` | Int | Секунд активности |
| `idle_sec` | Int | Секунд простоя |
| `fg_sec` | Int | Секунд в foreground |
| `bg_sec` | Int | Секунд в background |
| `screen_off_sec` | Int | Секунд с выключенным экраном |
| `crash_flag` | Boolean | Сессия закрыта крашем |
| `in_work_window` | Boolean | Сессия попала в рабочее окно |

### 3.2. `tab_visits`

| Поле | Тип | Описание |
|---|---|---|
| `id` | Long PK | Автогенерация |
| `session_id` | Long FK → sessions.id | CASCADE |
| `tab` | String | `main` / `search` / `stats` / `edit` / `db` / `settings` / `add` |
| `from_ts` | Long | Timestamp входа |
| `to_ts` | Long | Timestamp выхода (null если внутри) |
| `duration_sec` | Int | Длительность |

### 3.3. `order_work`

| Поле | Тип | Описание |
|---|---|---|
| `id` | Long PK | Автогенерация |
| `session_id` | Long FK → sessions.id | CASCADE |
| `order_id` | Long | ID наряда из основной БД |
| `area_title` | String | Денормализация — чтобы не терять при удалении |
| `order_title` | String | Денормализация |
| `started_at` | Long | Timestamp первого действия с нарядом |
| `ended_at` | Long? | Timestamp последнего действия (null если в работе) |
| `search_sec` | Int | Секунд в фазе «Поиск» |
| `verify_sec` | Int | Секунд в фазе «Сверка» |
| `status` | String | `in_progress` / `half_done` / `done` |
| `total_samples` | Int | Всего проб в наряде |
| `found_samples` | Int | Отмечено проб |

### 3.4. `events`

| Поле | Тип | Описание |
|---|---|---|
| `id` | Long PK | Автогенерация |
| `session_id` | Long FK → sessions.id | CASCADE |
| `at_ts` | Long | Timestamp |
| `level` | String | `info` / `warn` / `error` |
| `category` | String | `app` / `nav` / `search` / `voice` / `mark` / `edit` / `db` / `error` |
| `summary` | String | Русская фраза для UI |
| `details_json` | String? | JSON с техническими данными |
| `raw_voice` | String? | Сырой текст Vosk (только для `voice`) |
| `parsed_voice` | String? | Что понял парсер (только для `voice`) |

**Индексы:** `session_id`, `at_ts`, `level`.

### 3.5. `daily_summary`

| Поле | Тип | Описание |
|---|---|---|
| `date` | String PK | `YYYY-MM-DD` |
| `total_active_sec` | Int | Сумма активных по сессиям дня |
| `total_idle_sec` | Int | Сумма простоя |
| `runs` | Int | Сколько раз приложение запускалось |
| `ready_orders` | Int | Нарядов с полным прогрессом |
| `errors_count` | Int | Ошибок за день |
| `by_tab_json` | String | JSON: `{search: 1234, db: 567, ...}` |
| `updated_at` | Long | Timestamp последнего пересчёта |

**Пересчитывается:**
- при закрытии сессии;
- при первом запуске нового дня (если день ещё не в таблице).

## 4. Запись событий

### 4.1. Источник

`LogWriter` пишет события в `stats.db.events`:
- **`LogsDbCleanup`** удаляет `logs.db` при апдейте.
- **UI журнала из Настроек убран.**
- **`LogWriter`** пишет в `stats.db.events` с привязкой к `session_id`.

### 4.2. Логика сессий

- **`GeoSampleApp.onCreate`** — если есть незакрытая сессия
  (`ended_at == null`), закрываем её с `crash_flag = true`.
- Открываем новую: `started_at = now`.
- В `MainActivity.onPause` / `onResume` — учёт fg/bg времени.
- **`BroadcastReceiver` на `ACTION_SCREEN_OFF` / `ACTION_USER_PRESENT`** — учёт screen_off.
- **На выходе** (через `ExitBackupWriter` / `finishAffinity`) —
  закрываем сессию с `crash_flag = false`, пересчитываем
  `daily_summary`.

### 4.3. Трекер активности

- **Серия событий** — если между ними <60 сек, время считается
  активным.
- **Событий нет 60 сек** — начало простоя.
- **Любое действие** (тап, голос, навигация, ввод) — сбрасывает
  счётчик простоя.

### 4.4. Визиты вкладок

- **`NavGraph`** логирует вход/выход.
- Переиспользуем: `LaunchedEffect(currentScreen)` — вход,
  предыдущий — выход.
- Сессия может закрыться посреди визита — `to_ts` ставим при
  закрытии сессии.

### 4.5. Голос

Для каждого события `voice`:
- `raw_voice` — что услышал Vosk.
- `parsed_voice` — что понял `VoiceCommandParser`.
- Если совпадает в нормализованном виде — `info`.
- Если расходится — `warn`.
- Если команда не распознана — `error`.

### 4.6. Фазы наряда

**Начало работы с нарядом:** первое событие с упоминанием
наряда (поиск, отметка, открытие в редакторе).

**Модель:** последнее событие определяет фазу.
- Событие **поиск** → фаза SEARCH.
- Событие **отметка** → фаза VERIFY.

**Каждый интервал идёт в ту фазу, которой начался.** Интервал
между двумя событиями относится к фазе **первого** из них.

Пример: з1 → з2 → о1 → о2 → о3 → з4.
- з1→з2 — SEARCH;
- з2→о1 — SEARCH (интервал начался с поиска);
- о1→о2, о2→о3 — VERIFY;
- о3→з4 — VERIFY (интервал начался с отметки);
- з4 — открывает новый интервал, начинается SEARCH.

**Пауза**:
- **60 сек** между событиями в фазу **не идёт** (простой);
- **30 мин** без действий — закрывает наряд (`ended_at`,
  фиксация статуса). Следующий поиск того же наряда создаёт
  **новую запись** `order_work`.

**Статусы:**
- `in_progress` — работа идёт, не все пробы отмечены.
- `half_done` — поиск проведён, сверка не завершена.
- `done` — все `found = true`.

**Завершение наряда:**
- Все `found = true` — `done`.
- 30 мин без действий — `ended_at` закрывается, статус фиксируется.

### 4.7. Авто-повышение в warn

Серия неудач → `warn`:

- **5+ поисков подряд не нашли** → `warn`.
- **3+ одинаковых ошибки** → `warn`.
- **Краш + удаление БД за 5 мин** → `warn`.

6. Ротация
6.1. stats.db по месяцам
При старте приложения (GeoSampleApp.onCreate) — StatsRotator.checkAndRotate().

Что делает:
- читает MAX(sessions.started_at) из active.db (или mtime файла, если БД пуста);
- определяет месяц данных по локальной зоне;
- сравнивает с текущим месяцем;
- если совпадает — no-op;
- если разный — ротация.

Порядок ротации (критично, см. CONTEXT_BRIEF):

StatsDatabase.closeAndReset() — закрыть соединение, WAL откатится автоматически.
Удалить active.db-wal, active.db-shm (на всякий случай).
Переименовать active.db → filesDir/stats/archive/YYYY-MM.db.
Ничего не создавать — при следующем getInstance() активная БД создастся заново.

Защита:

При коллизии в archive/ (файл за этот месяц уже есть) — ротация не выполняется, warn в лог. Данные не теряются.
При I/O-ошибке (rename упал) — продолжаем писать в active.db, warn в лог. Данные важнее.

Ротация вызывается через runBlocking — чтобы гарантировать завершение до SessionTracker.onAppStart(). Иначе новая сессия уйдёт в active.db, который потом переедет в архив.

6.2. Удаление старых
Кнопка в админ-панели «Удалить данные за …»:

выбор периода: день / месяц / до даты.

подтверждение.

удаляет записи из stats.db.

удаляет соответствующие .stats/*.json.

логируется.

6.3. logs.db — удаляется
LogsDbCleanup.cleanupIfNeeded(context) вызывается в GeoSampleApp.onCreate до LogWriter.init.

Удаляет logs.db + -wal + -shm, если файлы существуют.

Без конвертации в stats.db — события уже идут туда через LogWriter.

Идемпотентно — безопасно при каждом старте.
