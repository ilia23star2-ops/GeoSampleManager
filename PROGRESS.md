## Что сделано

### ✅ Этапы 1–4 — База проекта

1. **Скелет.** Drawer, 7 вкладок, навигация через `AppScaffold`.
2. **Room-БД.** 5 таблиц: `areas`, `orders`, `samples`, `order_wells`,
   `sample_notes`. DAO + Repository. Version = 1.
3. **Настройки импорта.** Дерево категорий, экспорт/импорт JSON,
   пользовательские префиксы участков, словари заголовков и типов.
4. **Excel-импорт.** Свой парсер `.xlsx`, `ExcelAnalyzer`, `AreaResolver`,
   `OrderNumberExtractor`, `SampleFilter`, многослойная очередь, ручной
   маппинг, обучение словарей, история импортов.

### ✅ Этап 5.1 — Каркас сверки

Полностью готов UI-экран «Сверка и поиск» + модели + состояние.

**Ключевые файлы:**
- `ReconciliationModels.kt` — модели и чистые функции.
- `ReconciliationState.kt` — @Stable, undo/redo (20 шагов).
- `ReconciliationDialogs.kt` — все диалоги сверки.
- `ReconciliationViewModel.kt` — AndroidViewModel + БД.
- `ReconciliationMapper.kt` — мапперы.
- `SearchScreen.kt` — плоский `LazyColumn`.

**Реализовано на экране:**
- Селекторы участка и наряда.
- Поиск по скважине/пробе, фонарик-индикатор.
- Группировка: выбранный наряд сверху, чужие — ниже с подсветкой.
- Логика чек-бокса: найдена / ВК / холостая / отложена / ошибка.
- Диалоги веса, характеристик, редактора, удаления.
- Настройки наряда: холостые (FIXED/AVERAGE/MANUAL) + шаг ВК.
- Массовая отметка с диалогом решений.
- Undo/Redo со статус-баром.
- Динамический заголовок «Скважина / Выработка».
- Легенда символики.

### 🟡 Этап 5.9 — Room (частично закрыт)

**Работает:**
- `ReconciliationViewModel` загружает всё из БД.
- Одиночные действия — атомарные UPDATE без чтения.
- Групповые — `saveRows` (батч-`@Update` в транзакции).
- Удаление — `deleteSampleWithRenumber` с пересчётом номеров.
- Undo/redo — `persistAll` через `saveRows`.

**Осталось в 5.9:**
- ⬜ SQL-статистика для больших нарядов (если UI начнёт тормозить).
- ⬜ Diff-persist после undo/redo (сохранять только изменённые строки).

### ✅ Этап 5.5 — Заметки и фото (полностью закрыт)

**Что сделано:**

**5.5.1 — Инфраструктура**
- FileProvider в `AndroidManifest.xml`, `res/xml/file_paths.xml`.
- Разрешение `CAMERA`.
- `data/util/PhotoStorage.kt` — создание временного файла, Uri для камеры,
  сжатие (1024 px, JPEG 80%), сохранение, удаление.
- `data/entity/SampleImageEntity.kt` — таблица `sample_images`.
- `data/dao/SampleImageDao.kt` — CRUD + счётчики.
- Миграция БД **1 → 2**: `samples.has_photo`, `sample_notes` без `image_path`,
  новая таблица `sample_images`.
- Методы в `DatabaseRepository`: `addPhoto`, `deletePhoto`,
  `getPhotosForSample`, `getNoteWithPhotos`, `syncHasNoteAndPhoto`.
- Очистка файлов фото при `clearOrder` и `deleteSampleWithRenumber`.

**5.5.2 — Диалог заметки и фото**
- `NotePhotoDialog` в `ReconciliationDialogs.kt`:
  текстовое поле, LazyRow превью, кнопки «Сделать фото» / «Из галереи»,
  крестик на миниатюре для удаления.
- Защита от закрытия с несохранённым текстом.
- Лаунчеры `TakePicture` (системная камера) и `PickVisualMedia` (галерея).
- Подключение к `ReconciliationViewModel`.
- Декодирование миниатюр в `Dispatchers.IO` — UI не виснет.
- Все операции с заметкой/фото уведены в `Dispatchers.IO`.

**5.5.3 — Отображение и синхронизация**
- В `SampleRow` (UI) — `hasNote`, `hasPhoto`.
- `ReconciliationMapper.toRow()` берёт `hasPhoto` из `SampleEntity`.
- Иконки в строке пробы — точки входа в диалог.
- Флаги `has_note` / `has_photo` синхронизируются в репозитории.

**Проверено вручную:**
- Заметка сохраняется, переживает перезапуск.
- Фото добавляются из галереи, удаляются, переживают перезапуск.
- Иконки отображаются после перезапуска.
- Закрытие диалога с несохранённым текстом требует подтверждения.
- UI не виснет.
