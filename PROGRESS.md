## Как продолжить работу в новом чате

1. Прикрепи к первому сообщению **три файла**:
    - `README.md`
    - `PROGRESS.md` (этот файл)
    - `DECISIONS.md` (решения по UI и логике)
    - `NEXT_STEPS.md` (план следующих заходов)
    - `DATABASE.md` (как устроена БД — уже был раньше)
2. Скажи: «Изучи файлы в корне репозитория, продолжаем работу над этапом N».
3. Все правила проекта — в первом сообщении `README.md`.

**Ключевые правила проекта:**
- Kotlin + Jetpack Compose + Room.
- Комментарии и UI — на русском.
- Никакого Apache POI — свой парсер .xlsx.
- Целевые устройства — планшеты, адаптивность под телефон.
- Аудитория — простые рабочие, крупные элементы, понятные формулировки.
- Настройки автосохраняются, кнопки «Сохранить» нет.
- Всегда присылать **полные файлы** с полным путём.

## Что сделано

### Этапы 1–4 — завершены

1. **Скелет приложения.** Drawer с 7 вкладками: Главное меню, Добавить наряд,
   Сверка и поиск, Статистика, Редактирование, Управление БД, Настройки.
2. **Room-БД.** 5 таблиц: `areas`, `orders`, `samples`, `order_wells`, `sample_notes`.
   DAO, Repository, миграции не нужны (version = 1).
3. **Настройки импорта.** Дерево категорий, экспорт/импорт JSON, запоминание
   пользовательских префиксов участков и словарей.
4. **Полный Excel-импорт.** Свой парсер `.xlsx`, `ExcelAnalyzer` с гибридным
   автодетектом шапки и ролей, `AreaResolver`, `OrderNumberExtractor`,
   `SampleFilter`, многослойная очередь листов, ручной маппинг колонок
   (`MappingEditorDialog`), обучение словарей «на лету», история импортов.

### Этап 5.1 — каркас сверки (завершён)

**Файлы в `app/src/main/java/com/example/geosamplemanager/ui/screens/`:**

- `ReconciliationModels.kt` — UI-модели (`SampleGroup`, `SampleRow`, `GroupStats`,
  `MatchInfo`, `UndoAction`, `WellCellSnapshot`), чистые функции (фильтры,
  сортировка, статистика, поиск совпадений).
- `ReconciliationState.kt` — состояние экрана, undo/redo (20 шагов),
  логика раскрытия групп, все действия над пробами.
- `ReconciliationDialogs.kt` — все диалоги: `WeightDialog`,
  `CharacteristicDialog`, `NoteDialog`, `EditSampleDialog`, `DeleteSampleDialog`,
  `OrderSettingsDialog`, `ConfirmResetBlankWeightDialog`, `BulkActionsDialog`,
  `AlreadyFoundDialog`, `ImportErrorDialog`, `PostponedDialog`.
- `ReconciliationViewModel.kt` — AndroidViewModel, синхронизация с БД через
  `DatabaseRepository`. Атомарные UPDATE для одиночных действий.
- `ReconciliationMapper.kt` — мапперы `Entity ↔ UI`.
- `SearchScreen.kt` — экран на плоском `LazyColumn` (каждая строка — отдельный item,
  рендерится лениво).

**Реализовано на экране «Сверка и поиск»:**

- Селекторы участка и наряда, оба опциональны. Наряды зависят от участка.
- Поле поиска по номеру скважины или пробы (с префиксом или без).
- Фонарик слева от поиска: горит, если ответ единственный.
- Рядом с фонариком — название наряда-владельца.
- Группировка результатов: выбранный наряд — сверху, чужие — ниже с подсветкой.
- Чек-бокс «найдена» со всей логикой (ВК, холостая, отложена, ошибка).
- Диалог веса ВК и холостых.
- Настройки наряда: холостые + весовой контроль.
- Массовая отметка с диалогом решений.
- Удаление с переключателем пересчёта номеров.
- Undo/Redo с счётчиком и статус-баром.
- Счётчики групп и статистика — считаются на лету.
- Динамический заголовок «Скважина / Выработка».
- Легенда символики.
- Цветовая индикация строк по приоритету.

### Этап 5.9 — Room (частично завершён)

**Что уже работает:**

- `ReconciliationViewModel` загружает все участки, наряды и пробы из БД.
- Строит `SampleGroup` через `buildSampleGroup` из `ReconciliationMapper`.
- Каждое действие синхронизируется в БД:
    - одиночные — атомарными UPDATE (без чтения строки),
    - групповые (bulk, clearAll, settings) — батч-`@Update` в транзакции,
    - удаление — `deleteSampleWithRenumber` в транзакции с пересчётом номеров,
    - undo/redo — `saveRows` для всех групп.

**Расширения в БД-слое:**

- `SampleDao` дополнен атомарными UPDATE:
  `setWeight`, `setWeightControl`, `setStatus`, `setHasNote`,
  `setSampleType`, `setMaterialDesc`, `setSampleNumber`, `setWellNumber`,
  `setInterval`, `updateAll`.
- `DatabaseRepository` дополнен методами для сверки:
  `setWeight`, `setWeightControl`, `setSampleStatus`, `setHasNote`,
  `saveRows`, `deleteSampleWithRenumber`, `deleteWellsForOrder`, `upsertNote`.

**Что осталось в 5.9:**

- `DB.md` и `README.md` — актуализировать под новые методы.
- SQL-статистика для больших нарядов (если UI-подсчёт начнёт тормозить).
- Миграции, когда добавим поля в `OrderEntity` / `AreaEntity`
  (см. `NEXT_STEPS.md` → «Изменения БД»).
