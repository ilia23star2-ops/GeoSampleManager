# Статус разработки GeoSample Manager

## Общая информация

Мобильное Android-приложение для управления геохимическими пробами.
Разрабатывается как порт десктопной версии (Python + Tkinter) на Kotlin + Compose.
Целевые устройства — планшеты (основной сценарий) и телефоны.

### Этап 4 — Импорт Excel ✅ (завершён полностью)

#### 4.1. Парсер .xlsx
- `XlsxReader` — собственный парсер без Apache POI
- Ленивое чтение: `readMetadata` + `readSheet` — экономит память

#### 4.2. Автодетект шапки и колонок
- `ExcelAnalyzer` — гибрид: текстовый матчинг + профили колонок
- Data-driven якоря: серийный №, скважина↔проба по префиксу,
  интервал по связности, вес, тип, характеристика
- Двух- и трёхрядковые шапки через `mergedHeader`
- Учёт пользовательских словарей из настроек

#### 4.3. Автоопределение участка и наряда
- `AreaResolver` — по префиксам номеров скважин из настроек
- `OrderNumberExtractor` — из имени файла, при неудаче из имени листа,
  правило «последнее число» или «всё имя»

#### 4.4. Фильтрация
- `SampleFilter` — пропуск бланков/стандартных образцов без данных
- Холостые всегда импортируются

#### 4.5. Многослойный импорт
- Очередь листов с кнопками: Пропустить / Импортировать /
  Авто для остальных / Отменить всё
- Прогресс-бар в реальном времени
- Сводный отчёт после импорта
- Автопропуск общих списков (>200 проб) с уведомлением

#### 4.6. Ручной маппинг колонок
- `MappingEditorDialog` — визуальный редактор 60/40
- Таблица слева, роли справа, цветовая кодировка (8 ролей)
- Клик по шапке колонки → назначение активной роли

#### 4.7. Обучение на лету
- Диалог «Запомнить для будущих импортов?» после ручного маппинга
- Слова попадают в `userHeaderKeywords` или `userTypeValueKeywords`
- Префикс участка сохраняется в `areaPrefixes`

#### 4.8. История импортов
- `ImportHistoryRepository` — JSON в filesDir/import_history.json
- Записи: файл, дата, счётчики, список обработанных листов
- Раскрытие записи: статус и причина по каждому листу
- Статусы: импортирован / заменён / общий список / уже в базе /
  пропущен / ошибка

#### 4.9. Проверка существующих нарядов
- Плашка в предпросмотре: «Наряд уже существует»
- Диалог при импорте: Добавить / Пропустить / Заменить
- Галочка «Применить ко всем похожим»

## Договорённости и правила

1. **Полные файлы, не фрагменты.** Пользователь не собирает код по частям.
2. **Полные пути к файлам.** Всегда указывать `app/src/main/java/...`
3. **Аудитория — простые рабочие.** Везде подсказки и понятные формулировки.
4. **Все настройки автосохраняются.** Кнопки «Сохранить» нет.
5. **Настройки перечитываются** при открытии экрана (`viewModel.reload()`).
6. **Словари не путать:** стандартные (read-only) vs пользовательские.
7. **Пользовательские слова имеют приоритет** над стандартными.
8. **Общие списки** (>200 проб) в авто-режиме пропускаются с сохранением имени.
9. **Бланки без данных** (нет интервала и веса) — пропускаются.
10. **Холостые пробы** всегда импортируются.
