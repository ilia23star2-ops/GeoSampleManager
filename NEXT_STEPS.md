## Текущий этап — 5.5. Заметки и фото

### Принятые решения

1. **Несколько фото на пробу.**
2. **Заметка и фото независимы:** может быть текст без фото, фото без текста,
   оба, ни одного.
3. Файлы фото — **внутреннее хранилище приложения**: `filesDir/sample_photos/`.
4. **Сжатие:** до 1024 px по длинной стороне, JPEG, качество 80%.
5. **Съёмка:** через `ActivityResultContracts.TakePicture()` + `FileProvider`.
6. **Галерея:** через `ActivityResultContracts.PickVisualMedia()`.
7. **Отображение в списке:** иконки заметки и фото в строке пробы + пункты
   в меню 3 точки.
8. Разрешения: явные не нужны, но в манифест — `CAMERA` и `FileProvider`.
9. **Один диалог** на заметку и фото: сверху текст (редактируемый),
   ниже — превью фото и кнопки управления.
10. Флаг `has_note` в `SampleEntity` синхронизируется при сохранении/удалении
    заметки. Для фото — добавить аналогичный `has_photo`.

### План работ (3 захода)

#### Заход 5.5.1 — Инфраструктура
- `FileProvider` в `AndroidManifest.xml`.
- `res/xml/file_paths.xml` — куда разрешаем писать.
- Разрешение `CAMERA` в манифесте.
- Утилита `PhotoStorage` (в `data/util/`):
    - создание временного файла для съёмки,
    - сохранение файла из Uri галереи,
    - сжатие до 1024 px, JPEG 80%,
    - удаление файла.
- Методы в `DatabaseRepository`: `addPhoto`, `deletePhoto`,
  `getPhotosForSample`, `getNoteWithPhotos`.
- Изменения БД (см. раздел ниже).

#### Заход 5.5.2 — Диалог заметки и фото
- `NotePhotoDialog` в `ReconciliationDialogs.kt`.
- Кнопки «Сделать фото», «Из галереи», «Удалить фото», «Сохранить».
- Превью фото — `LazyRow` с миниатюрами.
- Тап по миниатюре → полноэкранный просмотр.
- Подключение к `ReconciliationViewModel`.
- Запуск `TakePicture` и `PickVisualMedia` через `rememberLauncherForActivityResult`.

#### Заход 5.5.3 — Отображение и синхронизация
- В `SampleRow` UI-модели — поля `hasNote`, `hasPhoto`, `photos: List<String>`.
- В `SampleEntity` — добавить `has_photo: Boolean`.
- При загрузке проб читать фото одним запросом (по sample_id).
- Иконки в строке работают как точки входа в диалог.
- Синхронизация флагов `has_note` / `has_photo`.

### Изменения БД (требуют миграции)

**`SampleEntity`:**
- Добавить `has_photo: Boolean = false`.

**`SampleNoteEntity`:**
- Убрать `image_path` (стало неактуально).
- Оставить `note_text`, `sample_id`, `created_date`.
- Одно текстовое примечание на пробу.

**Новая таблица `sample_images`:**
id : Long (PK)
sample_id : Long (FK → samples.id, CASCADE)
image_path : String
created_date : Long

**Миграция:** версия БД 1 → 2. Либо `Migration`, либо (пока не заботимся
о сохранении данных) `fallbackToDestructiveMigration`.

## Следующие этапы

### Этап 5.8 — Голосовой помощник

**Вариант А** — микрофон на экране сверки.

Компоненты:
- `SpeechRecognizer` (распознавание).
- `TextToSpeech` (озвучка, короткая и чёткая).
- Bluetooth-гарнитура — роутинг звука и микрофона.
- Разрешения: `RECORD_AUDIO`, `BLUETOOTH_CONNECT` (Android 12+).

Сценарии:
- «Скважина 123» → TTS: «Скважина 123, наряд 5, N проб».
- «Первая» / «Один» → отметка первой пробы.
- «Взвесьте» → диалог веса ВК.
- Отложенная → TTS: «Отложена. Заметка?»
- Все пробы отмечены → TTS: «Всё отмечено».
- Кнопка «стоп» всегда доступна.

## Открытые вопросы (обсуждаем по ходу)

1. **Вычисление номера пробы в скважине.** Сейчас считается в UI
   по формуле «`normalize(sample_number)` минус `normalize(well_number)`».
   Возможно, стоит хранить в БД как поле `number_in_well`. Обсуждается.
2. **SQL-статистика.** Пока считаем в UI. Если UI начнёт тормозить на больших
   нарядах — переведём на SQL-запросы.
3. **Автоматическая простановка ВК.** Сейчас флаг ВК ставит пользователь.
   Планируется: при импорте проставлять каждую N-ю рядовую пробу
   (холостые пропускаются). Настройка N — на наряд.
4. **Сохранение настроек холостых в БД.** Сейчас они в памяти `ReconciliationState`.
   Нужно ли переживать перезапуск приложения? Если да — добавляем поля
   в `OrderEntity`.

   обеспечить их согласованность с таблицами `sample_notes` / `sample_images`.

   равен `well_number`». Возможно, стоит добавить отдельный флаг
